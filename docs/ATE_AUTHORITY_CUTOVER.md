# ATE 权威存储迁移

## 目标与边界

会话、任务、消息和执行事实由 ATE 唯一持久化并直接查询。GSEA 不维护这些对象的第二份业务数据库、持久缓存或重型投影。ATE 不可用时，依赖事实提交的执行暂停，不回退到本地历史库。

GSEA 的 SQLite 只保留 checkpoint、运行时执行位置、调度租约、本地配置，以及在途请求的核对信息。这些数据通过 ATE 稳定身份和已提交位置关联。任务是否完成属于 ATE 事实；哪个本地 worker 正在执行属于运行时状态，不能以“调度状态”名义重复保存任务业务状态。

ATE 保持宿主无关。Agent Loop、调度规则、工具权限和语义判断仍由 GSEA 决定。ATE 负责有界记录、权限、顺序、原子提交、幂等回执、历史读取和来源关系。不得把 GSEA 的 SQLite 文件、SQL 模式或整库 JSON 镜像装入 ATE 来冒充迁移。

## 必须保留的原子性

- Session 事件批次与序列检查在 ATE 中一次提交。
- 创建子 Agent、关联执行与认领任务不能出现半完成状态。
- 任务细化的子任务、依赖关系和父任务版本一起提交。
- Agent 终态结果与父级消息具备同一次提交的保障。
- Execution admission、Turn/Execution/Step 绑定与恢复授权具有明确的提交顺序。
- 本地 checkpoint 写入失败不能撤销已提交的 ATE 事实，也不能触发工具重复执行。
- 外部副作用已发生但结果提交未知时，先核对原请求；无法核对的工具暂停，不盲目重做。

## 实施顺序与完成标准

1. 为 ATE 补齐宿主无关的 Session 身份、版本化元数据和只追加事件契约，覆盖原生 stdio、规范编码、权限和重新打开后的读取。
2. 分离 GSEA 应用装配对具体 SQLite 事实仓库的依赖，保留运行时存储边界。
3. 用 ATE 实现 Session、Task、Agent、消息和相关复合操作的仓库接口；列表与历史直接读 ATE。
4. 将经验历史与来源引用切到 ATE；停止生成完整历史的 temporal outbox，移除启动和关闭时的历史补送。
5. 将 CLI 会话目录和恢复入口切到 ATE；本地只保留资源关联与运行状态。
6. 验证丢失提交回执、工具结果后的断流、checkpoint 写入失败、重启恢复、任务原子性及跨会话经验采用。

“完成迁移”必须同时满足：

- 普通 CLI 路径不向 SQLite 的会话、编排事件或任务业务表写入新事实。
- 删除可重建的本地运行数据不影响从 ATE 查看已提交的会话、任务与历史；恢复执行仍遵守 checkpoint 的实际可用性。
- ATE 请求提交结果未知时不生成新的逻辑请求身份重放副作用。
- 无启动历史全量同步，也无业务数据双写。
- 全部相关测试通过，且原生 stdio 端到端验证覆盖新路径。

## 权威记录与运行时关联

GSEA 的编排对象逐条存入 ATE 的 `gsea-authority` 操作空间。这个空间是宿主基础设施的权限范围，不是经验的领域分类；语义 Space 仍由 Agent 动态发现和组织。

一次编排决策从同一个 ATE 历史截面读取相关对象，在 GSEA 中执行状态机验证，再以整个空间根的条件检查提交实体变化、事件和幂等记录。根检查也保护“没有未完成子任务”这样的集合条件。不会把整 Team 或数据库序列化成单个值。

任务重试需要同时证明失败执行没有不可重复的副作用。读取完原生 Session 历史后，改派事务在自己的历史截面核对 Session 序列，并用 ATE 全局提交栅栏保护最终写入。Session 追加与宿主状态分属不同根，仅检查宿主状态根不够；证明后追加历史会使改派冲突，不能沿用过期证明。

Session 事件使用 ATE 原生 Session 追加接口。Execution admission 与 Session 追加跨越两个命令，采用明确的准备、绑定、消费与恢复协议，不宣称两个独立提交天然原子。

本地新格式位于 `runtime-v3.db`，只包含运行时资源和未完成请求。启动不运行旧业务库迁移，也不回填历史 outbox。旧 `runtime.db`、`runtime-v2.db` 和 `sessions.db` 原地保留，当前默认路径不会读取或迁移它们；新库不包含会话、任务、消息或用量事实表。受支持的 ATE-linked runtime v1 库可以原地打开，保留 schema 及退役扩展资源行，但不读取其内容、不恢复扩展执行；新库不创建退役资源表。未知或混合格式仍拒绝打开，不能仅凭文件名判断格式。运行时绑定 ATE 的 Store ID，每次租用原生连接都检查身份，防止替换目录后误用另一个存储的 checkpoint。

可复用记忆的内容、来源与复用状态由 ATE Memory 管理。本次采用的记录由 ATE Knowledge 保存。策略规格、影子测试报告和策略回退状态独立存放。Turn/Flow 的冻结工具清单及引用属于本地运行资源，归档先取得 ATE 维护回执，再更新本地引用的释放标记。[跨任务记忆指南](../EVOLUTION.md)

请求结果未知时保留原始提交字节与稳定身份。得到经核验的 durable acknowledgement 后删除正文；明确拒绝后保留不含正文的终结标识，防止同一身份在以后条件变化时重新执行。关闭 App 不再补送历史。

通用启动核对只处理已有 ACK 和已持久化的明确拒绝，不发送缺少执行作用域的旧命令。Session 的上传与追加请求保留为一组；根会话取得执行锁后，依据 ATE 中的 Team 成员关系取得子会话锁，按上传→追加顺序恢复。上传确认被拒绝时，只能退役经核验从未尝试发送的依赖追加；已经尝试但结果未知的追加仍保留原请求。

共享 ATE 的多个运行进程以 Store ID 和 Session ID 获取会话执行锁；更换本地 `runtime-v3.db` 路径不能绕过同一会话的独占执行。Supervisor 启动恢复只处理本进程持有的 Team，不清理其他活跃会话的模型用量预留或任务认领。根会话创建和关闭互斥，避免提交期间提前释放执行锁。

控制查询直接读取 ATE，不创建 Supervisor 或打开本地运行库；控制修改先验证目标 Team 和所有输入身份，取得根会话执行锁，再完成目标会话已有的归档或放弃恢复操作。每条控制命令独立装配和释放资源，不会因读取列表而恢复其他 Team。

启动核对遇到已确认拒绝且正文清理成功的请求时，可以继续核对后续请求。结果未知、存储身份不匹配或正文清理失败会阻止依赖该事实的执行。当前 ATE 不保存拒绝回执；已经尝试发送却查不到回执的请求不能仅凭“当前未找到”自动重新提交，需要保留未知状态。

显式配置自动经验服务的嵌入宿主从所拥有的会话/Team 原生历史中发现待办。扫描与认领分别使用有界预算，认领通过原生 correlation 查询检查最新状态，并以 Session 序列 CAS 写入。扫描超时会保留待办，已完成的 Turn 保留原执行结果。普通 CLI 的记忆维护由主 Agent 按需调用工具并经过审批。
